# 模型会话记忆树

`memlong` 继续独立保存长期事实。会话树只负责历史经历、话题和状态变化。
聊天原文仍保存在 `memory/<用户>.json`，不迁移、不删减。

## 时间窗口

每条短期消息和长期记忆都使用结构化的 `created_at` 字段保存 ISO 8601 时间；正文不再拼接时间戳。读取旧数据时会识别原来的 `[YYYY-MM-DD HH:MM:SS]` 前缀并自动拆出时间。

发送给模型的最近消息、记忆树节点和 `mem_rag` 结果会在展示层补充可读时间。普通连续对话优先显示“刚才、今天 18:30、相隔几分钟”等紧凑表达；跨数月或数年的间隔会保留精确时间作为核对锚点。记忆树节点显示时间范围和持续时间，避免每条消息重复完整时间戳。精确时间始终保存在 JSON 元数据中，旧索引会从原始历史重新建立。

每条非 system 消息是一个叶子，包含工具动作和回显。默认每 4 个同层
节点生成一个父层摘要，向上重复。父摘要由模型归纳，成功后才标记 ready；
没有字符串拼接或截断的摘要替代方案。父层记录孩子引用、覆盖范围、摘要模型和提示词版本。
超长原文会分片提交模型，汇总所有分片，不会直接丢掉中间文本。

## 配置

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `memory_tree_enabled` | `true` | 关闭后恢复原来的最近 max_history 条消息 |
| `memory_tree_fanout` | `4` | 叉数，2–16 |
| `memory_tree_summary_chars` | `700` | 每个模型摘要最多字符数，128–2000 |
| `memory_tree_recent_messages` | `40` | 最近多少条非 system 消息保留原文 |
| `memory_tree_max_chars` | `6000` | 旧会话摘要视图字符预算；不含最近原文、系统提示词和 memlong |
| `memory_tree_model` | 空 | 空值复用主模型，可指定更便宜的摘要模型 |
| `memory_tree_base_url` | 空 | 空值复用主接口 |
| `memory_tree_api_key` | 空 | 空值复用主凭证 |
| `memory_tree_timeout` | `90` | 每次摘要请求的超时秒数 |

可通过 NoneBot 的环境变量或 `.env` 配置。索引为
`memory/trees/<用户>.v3.n<叉数>.c<摘要上限>.json`。更换叉数或摘要长度上限
会建立独立索引，重新生成模型摘要；已有 v2 索引和 v1 原型文件保留。
更换模型影响后续新增摘要，已有摘要不会自动重算。

## 窗口和成本

固定叉数 b 时，持有的根节点每层最多 b−1 个。把跨最近原文边界的根拆开，
选出的节点仍为 O(b log_b n)；固定 b 即 O(log n)。摘要内容有长度上限，
但最近原文、长期事实和系统提示词长度另计。空间为 O(n)，不是 O(log n)。
新消息触发的父摘要均摊少于 1/(b−1) 次调用，最坏单条会连续提升 O(log_b n) 层。
一次完整历史回填约需 n/(b−1) 个父摘要，超长原文分片和失败重试会增加调用。
叉数增大降低层数和回填调用数，但父层要同时压缩更多孩子，且同层未合并节点可能更多。

正常对话每个用户在进程内共享一个后台摘要线程，不阻塞聊天请求。
完成一条父摘要就原子保存；重启后继续处理 pending 节点。失败后保留原文及子层，
30–300 秒退避后由下一次对话触发重试。回填期间待生成节点会明确标注，
因此旧历史的摘要覆盖质量要等后台回填完成后评估。

窗口始终保留覆盖范围；预算不足时优先保留节点索引以供展开，
不会无提示地丢弃后面的时间段。`mem_expand` 支持 `depth`、`offset`、`max_chars`，
可逐层阅读和分页取回完整原话；`mem_rag` 继续检索原始日志与独立长期记忆。

## 离线回填

在插件目录运行。离线工具读取现有 Config 默认值、机器人 `.env` 和环境变量，
不启动 NoneBot，不写原始消息或 memlong：

```powershell
python tools/build_memory_tree.py --user-id 123456789 --dry-run
python tools/build_memory_tree.py --user-id 123456789 --max-nodes 5
python tools/build_memory_tree.py --user-id 123456789
python tools/build_memory_tree.py --user-id 123456789 --workers 4
```

`--dry-run` 只生成树的索引结构。不要同时用离线工具和运行中的 v3 机器人
写同一个索引；进程间不共享线程锁。停止回填后重新运行同一命令即可续建。
日志只报告节点数量和错误类型，不输出原文或完整服务响应。

## 验证

```powershell
python -m unittest discover -s tests -p 'test_*.py'
```

覆盖 n 叉进位、窗口连续覆盖与规模上界、真实模型摘要接口契约、失败不落盘为事实、
进度复用、日志编辑失效、共享后台线程和长原文分页。模型归纳仍可能遗漏细节，
需要准确引用时应展开原文；不能把自动摘要当成已核实的新事实。
